# 求职跟进智能体

面向求职者的机会跟进工作台。系统根据招聘阶段、对话承诺、工作时间和历史追问次数，生成下一次追问计划与消息草稿，并默认由用户确认后发送。

当前仓库包含可交互的产品骨架、真实用户入门流程、独立调度领域模块、账号认证、SQLite/PostgreSQL 持久化、自动化测试和 GitHub CI。每个账号拥有隔离的空工作区；真实消息渠道属于后续阶段。

## 核心原则

- 不编造求职者经历、薪资、到岗时间或其他个人事实。
- 招聘方回复、明确拒绝或岗位关闭后，立即取消失效任务。
- 单个机会默认最多主动追问两次。
- 避开夜间、周末和法定节假日。
- 第一阶段所有外发消息均需用户确认。
- 所有发送操作都需要幂等键和审计记录。

## 本地运行

要求 Node.js 22 或更高版本。

```bash
npm install
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。

未配置数据库连接时，首次请求会创建 `.data/followup.db`。注册账号后，系统会为该账号创建独立的空工作区，引导用户确认求职目标并添加第一个真实机会。可以在 `.env.local` 中修改 SQLite 路径：

```bash
DATABASE_PATH=/absolute/path/to/followup.db
```

设置 `DATABASE_URL` 后会优先使用 PostgreSQL，并在启动时自动执行版本化迁移：

```bash
DATABASE_URL=postgresql://user:password@localhost:5432/career_followup
```

托管数据库应在连接字符串中使用供应商要求的验证模式和 CA 配置，不要关闭证书校验。密码使用 scrypt 加盐哈希；登录状态使用 30 天有效的随机会话令牌，Cookie 设置为 HttpOnly、SameSite=Lax，并在生产模式下启用 Secure。

登录与注册使用数据库持久化限流。部署在会清理并重写转发头的可信反向代理之后时，可以启用客户端 IP 维度：

```bash
TRUST_PROXY_HEADERS=true
```

不要在应用直接面向公网时启用该选项，否则客户端可以伪造 `X-Forwarded-For`。`AUTH_RATE_LIMIT_ENABLED` 默认开启；仅在数据库限流故障且外围网关已有替代保护时，才应临时设为 `false`。

首批用户采用人工确认收款。先注册运营账号，从 `GET /api/auth/session` 读取自己的 `user.id`，再将该 ID 配置为逗号分隔的服务端环境变量。重新部署后，该账号可访问 `/admin`：

```bash
ADMIN_USER_IDS=3c77b866-5103-44de-b2c3-5db540254324
```

生产环境不允许按未验证邮箱授权。`ADMIN_EMAILS` 只用于本地开发和自动化测试，生产模式会忽略它。

普通用户可在“冲刺版”提交购买申请；提交申请不会自动扣款或开通权益。运营人员实际收到 `99 元` 后，在管理员页面确认收款，系统才记录 30 天服务起止时间。联系方式只从受保护的运营接口返回，不写入普通工作区响应或审计事件。详细操作见 [首批用户运营手册](docs/PILOT_OPERATIONS.md)。

当前版本尚未完成邮箱验证、密码找回、联系方式加密和数据删除，因此仍只用于受控邀请测试，不要直接开放注册或录入真实简历与招聘对话。正式公网获客前必须先完成这些安全能力和隐私文本。
