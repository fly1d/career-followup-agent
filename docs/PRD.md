# 产品需求文档

## 1. 产品定义

求职跟进智能体帮助求职者管理分散的求职机会，并在合适的时间，用合适的内容跟进招聘方。简历生成、转换和岗位筛选是后续支撑能力，首要目标是把“追问”做得可靠、克制且可控。

## 2. 当前范围

### 包含

- 记录岗位、招聘方、投递渠道和求职阶段。
- 从对话中提取招聘方承诺的反馈日期。
- 根据阶段和承诺计算下次跟进时间。
- 生成能够解释依据的追问草稿。
- 在信息不确定时追问求职者，并按作用范围保存记忆。
- 用户确认、编辑、延后或跳过追问。
- 招聘方回复、岗位关闭或用户放弃后取消任务。
- 保存机会时间线、消息版本和操作审计。

### 暂不包含

- 模拟面试。
- 未经明确授权的全自动投递。
- 未经用户确认的薪资、Offer、离职原因和到岗承诺。
- 绕过招聘平台验证码、风控或服务条款。

## 3. 核心用户流程

1. 用户注册并确认目标岗位、城市、求职阶段和现有机会数。
2. 用户添加第一个真实岗位或导入招聘沟通。
3. 系统识别机会阶段和招聘方承诺。
4. 调度引擎生成下一次追问时间并说明原因。
5. 到期后系统重新检查最新上下文。
6. 智能体生成追问草稿；缺少事实时先询问用户。
7. 用户确认、编辑、延后或跳过。
8. 发送结果写入时间线，并安排或停止后续任务。

## 4. 状态模型

```text
发现岗位
→ 准备投递
→ 已投递
→ 等待回复
→ 招聘沟通
→ 面试安排
→ 面试完成
→ 等待结果
→ Offer 沟通
→ 已录用 / 已拒绝 / 已放弃
```

终态不得再产生主动追问任务。面试已经安排时只生成提醒，不生成询问招聘进度的消息。

## 5. 调度规则

| 场景 | 默认时间 | 停止条件 |
| --- | --- | --- |
| 投递后无回复 | 3 个工作日 | 回复、拒绝、关闭 |
| 已查看简历无回复 | 2 个工作日 | 回复、拒绝、关闭 |
| 招聘方承诺反馈 | 承诺结束后的下一个工作日 | 回复、拒绝、关闭 |
| 面试结束无结果 | 3 个工作日 | 回复、拒绝、关闭 |
| 补充材料后无回复 | 2 个工作日 | 回复、拒绝、关闭 |
| 首次追问后无回复 | 至少 4 个工作日 | 第二次后永久停止 |

默认发送窗口为工作日 09:30 至 18:30。节假日规则通过可更新日历提供，不硬编码在模型提示词中。

## 6. 记忆范围

- `长期事实`：教育、经历、技能等稳定事实。
- `求职偏好`：城市、岗位、薪资和排除条件。
- `单机会决定`：仅对某个岗位有效的薪资或到岗例外。
- `单次授权`：只允许用于当前消息的敏感信息。

每次记忆更新必须保存来源、时间和作用范围。单机会决定不能覆盖全局偏好。

## 7. 关键验收标准

- 相同追问任务即使被重复执行，也只能发送一次。
- 招聘方回复后，旧追问任务在下一次执行前被取消。
- 已拒绝、关闭和已放弃机会不会生成追问。
- 达到最大追问次数后不会继续循环。
- 智能体缺少敏感事实时必须向用户提问，不能推断。
- 用户可以看到“为什么现在追问”和系统使用了哪些信息。
- 每次发送都能追溯草稿版本、确认人、渠道、时间和结果。

## 8. 里程碑

### M0：可验证产品骨架

本地交互、领域规则、核心页面、单元测试、冒烟测试和 CI。

### M1A：本地服务端持久化（已完成）

单工作区 API、SQLite、机会与追问持久化、设置持久化、审计日志和浏览器重载验收。该阶段只面向本地开发，不对公网提供真实用户服务。

### M1B：账户认证与工作区隔离（已完成）

注册、登录、退出、可撤销会话、密码安全存储、账号工作区隔离和所有业务 API 鉴权。

### M1C：生产持久化与账户加固（进行中）

已完成 PostgreSQL 连接池、版本化迁移、事务、数据库租户关系约束、真实方言集成测试，以及数据库持久化的登录/注册限流。待完成对象存储、邮箱验证、密码找回、数据导出与删除。

### M1D：首批付费用户激活闭环（已完成）

新账号不再写入演示机会。用户先确认目标岗位、城市、求职阶段和当前机会数，再添加第一个真实机会。系统以幂等审计事件记录注册、完成入门、添加首个机会、生成首个追问和确认首个追问，为首批用户陪跑和付费转化分析提供统一口径。

商业验证阶段主推“求职冲刺版”：99 元 / 30 天，前 10 位用户包含 AI 生成与人工复核。首个目标是 10 位真实付费用户，不承诺获得 Offer。支付接入前可以人工确认收款，但必须记录权益开始与结束时间。

当前已完成产品内购买申请、管理员人工确认实际收款、30 天权益起止时间、10 人名额上限和激活/付费漏斗。申请不等于付款，系统不会自动扣款；只有生产管理员白名单账号能够确认收款。公开获客前仍需完成邮箱验证、密码找回、联系方式加密、数据删除、隐私与服务条款和退款流程。首批用户在这些门槛完成前只通过受控邀请进入。

### M2：可靠调度

持久化队列、工作日历、失败重试、幂等发送、通知和可观测性。

### M3：对话智能

对话导入、结构化提取、提示词版本管理、评测集和用户澄清流程。

### M4：受控渠道集成

在平台规则允许的范围内接入邮箱或开放 API；默认保持发送前确认。
